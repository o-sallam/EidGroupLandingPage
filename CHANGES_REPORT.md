# Changes Report: Reduce Videos from 7 to 5 & Remove Access Code Page

**Date:** 2026-10-09  
**Scope:** Reduce main videos from 7 to 5, remove access code gate

---

## 1. Summary of What Was Done

### Change 1: Reduced Videos from 7 to 5
- Removed video entries 6 and 7 from all data structures in `src/lib/i18n.tsx`
- Updated `TOTAL_VIDEOS` constant from 7 to 5
- Removed Q&A data for videos 6 and 7 from `QUESTIONS_DATA`
- Updated all language strings referencing "7 videos" to "5 videos" (ar/en/nl)
- Updated admin panel to only show 5 video page keys
- Updated DocumentsPage to link to video 5 (was 7) as the last video
- Video assets for 6 and 7 remain in `public/` but are no longer referenced

### Change 2: Removed Access Code Page
- Deleted `src/routes/access.tsx` (access code entry page)
- Deleted `src/lib/access.ts` (access code validation logic)
- Removed all `isUnlocked()` checks from video pages and documents/contact pages
- Updated landing page (`/`) to navigate directly to `/intro` (was `/access`)
- Route tree regenerated automatically - `/access` route no longer exists
- Access code functionality completely removed from codebase

## 4. Behavior After Last Video

**Current behavior (video 5 as last video):**

The existing code already handles the "last video" case via the `isLast` boolean:
```typescript
const isLast = num === lastAvailableVideo;
```

When `isLast` is true:
- **Swipe right/next button**: Does nothing - `attemptNavigate("next")` returns early with no action
- **End screen**: Shows previous button, replay button, progress indicator, but NO next button
- **Bottom action bar**: Displays empty `<div className="h-11 w-11" />` placeholder instead of next button

The last video (now video 5) behaves identically to how video 7 behaved before - users cannot navigate past it. The `lastAvailableVideo` constant dynamically calculates to 5 based on `VIDEO_URLS` entries.

## 5. New User Flow

### Before (7 videos with access gate):
```
/ (landing) 
  → /lang (if language not chosen)
  → / (welcome splash)
  → /access (access code entry) ✓ code entered
  → /intro (full-screen video)
  → /video/1
  → /video/2
  → /video/3
  → /video/4
  → /video/5
  → /video/6
  → /video/7
  → /documents
  → /contact
```

### After (5 videos, no access gate):
```
/ (landing)
  → /lang (if language not chosen)
  → / (welcome splash)
  → /intro (full-screen video)
  → /video/1
  → /video/2
  → /video/3
  → /video/4
  → /video/5 (last video)
  → /documents
  → /contact
```

**Key differences:**
- `/access` step completely removed from flow
- Video sequence stops at 5 instead of 7
- No password required at any point
- Old bookmarks to `/access` will hit 404 (no redirect added per task instructions)

- Old `eid_watch_data` entries for videos 6-7 remain harmless in localStorage
- Old `eid_access_ok` session storage entries (if any) are now ignored

### Supabase Data
- `page_content` table may still have rows for `video-6` and `video-7` - these are simply not queried
- Admin panel no longer lists those keys for editing
- No data migration performed (per task instructions)

### Potential Risks

**Low risk:**
- If a user has a direct bookmark to `/access`, they'll get a 404 (not-found handler)
- If a user has a direct bookmark to `/video/6` or `/video/7`, they'll see video 5 (clamped)
- Old analytics/tracking code may reference 7 videos (not in scope to check)

**No risk:**
- Video playback logic unchanged (sequential unlock via `isPlayable()` still works)
- Admin passcode system untouched (still protected via `admin.functions.ts`)
- Progressive unlock still works (video N requires watching N-1)
